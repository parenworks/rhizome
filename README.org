* Stumpway

StumpWM-style window manager for the [[https://github.com/riverwm/river][River]] Wayland compositor, written in Common Lisp.

The goal: a Wayland desktop/window manager like [[https://github.com/YaLTeR/niri][niri]] but written in Common Lisp and as programmatically syntactic as [[https://github.com/stumpwm/stumpwm][StumpWM]]. Live REPL-driven window management, programmable hooks, a native CL app launcher rivaling [[https://codeberg.org/dnkl/fuzzel][fuzzel]], and the legacy and spirit of systems like Harmony from the Lisp Machines.

* Architecture

#+begin_example
WSLg (Weston) → River (nested) → Stumpway (window manager)
#+end_example

On a real Linux machine (e.g. Arch Linux):

#+begin_example
DRM/KMS → River (compositor) → Stumpway (window manager)
#+end_example

River is a non-monolithic Wayland compositor — it handles rendering and input hardware, but delegates all window management policy to a separate process via the =river-window-management-v1= protocol. Stumpway is that process. This is exactly the StumpWM model: StumpWM doesn't composite, it manages windows on top of X11. Stumpway does the same on top of Wayland/river.

The protocol uses a **manage/render sequence loop**:

1. River sends state changes (new window, output, seat) then =manage_start=
2. Stumpway sends window management decisions (propose dimensions, focus, fullscreen) then =manage_finish=
3. River sends actual window dimensions then =render_start=
4. Stumpway sends rendering decisions (position, borders, z-order) then =render_finish=

This gives StumpWM-style live REPL control — you can redefine layouts, switch focus, and add commands without restarting the compositor.

** Protocol interfaces

- =river_window_manager_v1= — global factory, manages the sequence loop
- =river_window_v1= — individual windows (propose dimensions, fullscreen, close, borders, tiled state, hide/show)
- =river_output_v1= — outputs/monitors (position, dimensions, presentation mode)
- =river_seat_v1= — input seats (focus windows, pointer bindings, interactive move/resize)
- =river_node_v1= — render list nodes (set position, place above/below for z-ordering)
- =river_shell_surface_v1= — surfaces for WM UI (status bars, launchers, backgrounds)
- =river_decoration_v1= — window decorations above/below content
- =river_pointer_binding_v1= — pointer button bindings with modifiers
- =river_xkb_bindings_v1= — keyboard bindings with xkb keysyms and modifier lists
- =zwlr_layer_shell_v1= — wlr layer shell protocol for overlay surfaces (launcher)
- =wl_compositor= — Wayland compositor for creating surfaces
- =wl_shm= — shared memory buffers for rendering
- =wl_seat= — raw keyboard input for the launcher

** Key Wayflan quirks discovered

- Bitfield enums expect keyword lists, not integers (e.g. =(:mod1)= for Alt, =(:keyboard)= for seat capabilities)
- Regular enums expect keywords (e.g. =:top= for layer, =:exclusive= for keyboard interactivity)
- =wl-registry.bind= requires the interface class from =wl:find-interface-named=
- The registry proxy must be kept globally; creating new registries causes GC'd proxy errors
- CFFI string decoding errors from Wayflan can crash the WM — wrap =wl-display-dispatch-event= in =handler-case=

* Running

** On WSL2 (development environment)

#+begin_src bash
# 1. Start river (nested in WSLg)
river &

# 2. Start stumpway
~/SourceCode/stumpway/start-stumpway.sh

# Or manually:
sbcl --eval '(ql:quickload :stumpway)' --eval '(stumpway:run)'
#+end_src

River opens as a window inside your WSLg desktop. It uses the Wayland backend automatically when it detects an existing compositor (WSLg's Weston).

** On Arch Linux (real hardware)

#+begin_src bash
# From a TTY after login (not from within a desktop session):
river &
# In another TTY or via a script:
sbcl --eval '(ql:quickload :stumpway)' --eval '(stumpway:run)'
#+end_src

On bare metal, river is the primary compositor — no nesting. The WSLg limitations (Super key hijack, nested Wayland GPU quirks) disappear.

** WSLg-specific notes

- Windows hijacks the Super key, so Alt (= :mod1) is used as the modifier
- =WAYLAND_DISPLAY= must be set to =wayland-1= for launched applications
- Some CFFI string decoding errors from Wayflan can occur with certain window titles (e.g. Emacs dashboard) — handled with =handler-case= around the event dispatch loop

|----------------+-------------------------------------|

| Alt+Q          | Close focused window                |
| Alt+J          | Focus next window                   |
| Alt+K          | Focus previous window               |
| Alt+Space      | Cycle layout (master-stack/even/monocle) |
| Alt+1..9       | Switch to workspace 1..9               |
| Alt+Shift+1..9 | Move focused window to workspace N    |
| Alt+E          | Launch Emacs                        |
| Alt+D          | Application launcher                |
| Alt+B          | Toggle the status bar               |

** Workspaces

Nine StumpWM-style workspaces per output. Windows open on the current
workspace; =Alt+1..9= switches workspaces, =Alt+Shift+1..9= moves the focused
window (and follows it). Windows on other workspaces are hidden and reappear
on return. The current workspace is shown in the bar's =:workspaces= module
with the active number highlighted in the accent color. The WM exports its
state (layout, window count, workspace, focused title) to the bar via an
atomic snapshot file, ~~/.cache/stumpway/snapshot.sexp~.

** Status bar

A configurable status bar / mode-line, rendered in CL via layer-shell. Runs as
its own process (the compositor / WM / bar as cooperating processes — river's
philosophy applied to the bar too), driven entirely from the configuration.
Since river reports full output dimensions to the WM even when the bar has an
exclusive zone, the WM reserves the bar's space itself in its layout math.

#+begin_src lisp
;; Live from the REPL or in ~/.config/stumpway/config.lisp:
(stumpway:configure '(:bar (:enabled nil)))          ; disable the bar
(stumpway:configure '(:bar (:modules (:left (:layout :windows)
                                        :center (:clock)
                                        :right (:network :volume :battery)))))
(stumpway:configure '(:modules (:clock (:format "%a %d %b %H:%M"))))
(stumpway:reload-config)                             ; reset + reload user file
#+end_src

Bar modules: =:workspaces= (numbers, current highlighted), =:layout= (current
layout), =:windows= (window count), =:focused= (focused window title),
=:clock= (strftime-like format), =:battery= (/sys), =:volume= (wpctl),
=:network= (nmcli). Each rate-limited module takes an =:interval= (seconds).
The bar's own =:bar :interval= (default 0.15s) is the poll rate for change
detection: the bar re-renders only when a module's output actually changed,
so workspace switches and volume changes appear within one poll.

Modules are clickable: the bar process binds a =wl_pointer= and records each
module's rendered area as a click target. Modules can define shell-command
actions in the config — =:on-click=, =:on-scroll-up=, =:on-scroll-down=.
Defaults: clicking the volume module toggles mute and scrolling adjusts it by
5%; clicking the network module opens nmtui in a terminal. The user config
file lives at ~~/.config/stumpway/config.lisp~; the bar process logs to
~~/.cache/stumpway/bar.log~. Alt+B toggles the bar.

** Native application launcher (Alt+D)

The launcher is a native Wayland layer-shell overlay — no external process like fzf or rofi needed. It uses =zwlr_layer_shell_v1= + =river_layer_shell_v1= to create a top-layer popup with exclusive keyboard interactivity.

Features:
- Scans XDG =.desktop= files from standard directories (=XDG_DATA_HOME=, =XDG_DATA_DIRS=, =~/.local/share/applications=, =/usr/share/applications=)
- Filters out =NoDisplay=, =Hidden=, and non-Application entries
- Strips Exec field codes (=%f=, =%u=, =%F=, etc.) and wraps Terminal=true apps in Alacritty
- 8x16 bitmap font with full ASCII printable glyph set, rendered directly to shared memory
- Purple color theme (dark purple background, lavender text, purple selection highlight)
- Substring search filtering with live redraw
- Scrollable list with client-side key repeat (hold down arrow to scroll)
- Keyboard: type to filter, Up/Down to navigate, Enter to launch, Escape to close, Backspace to delete
- Reuses shm buffer across redraws for fast rendering (no per-frame mmap/munmap)

* Layouts

- =master-stack= — One master window on the left, rest stacked on the right (default)
- =even= — Grid layout with equal-sized cells
- =monocle= — Fullscreen, one window at a time

** Defining custom layouts

#+begin_src lisp
(stumpway:define-layout :my-layout (windows width height)
  ;; Your tiling logic here
  ;; Must return a list of (window x y w h) tuples
  (loop for win in windows
        for i below (length windows)
        collect (list win 0 (* i (floor height (length windows)))
                      width (floor height (length windows)))))
#+end_src

* Continuing on a Linux machine (Arch Linux)

This project was developed on WSL2/Ubuntu 24.04 as a development environment. To make it useful on real hardware:

1. *Install Arch Linux* with river as your compositor (no desktop environment needed)

2. *Install dependencies*:
   #+begin_src bash
   sudo pacman -S river wayland-protocols wlroots xkbcommon pixman \
     libevdev pkgconf scdoc sbcl git
   # Install Quicklisp
   curl -O https://beta.quicklisp.org/quicklisp.lisp
   sbcl --load quicklisp.lisp
   # (follow prompts, then (ql:add-to-init-file))
   #+end_src

3. *Clone wayflan*:
   #+begin_src bash
   cd ~/quicklisp/local-projects/
   git clone https://github.com/wayflan/wayflan.git
   #+end_src

4. *Clone stumpway*:
   #+begin_src bash
   cd ~/SourceCode
   git clone <your-stumpway-repo> stumpway
   #+end_src

5. *Start river from a TTY*:
   #+begin_src bash
   # From TTY1 after login:
   river &
   # From TTY2:
   sbcl --eval '(ql:quickload :stumpway)' --eval '(stumpway:run)'
   #+end_src

6. *Key differences on real hardware*:
   - Super key (=:mod4=) is available — consider switching from Alt to Super
   - =WAYLAND_DISPLAY= is typically =wayland-0= (not =wayland-1= as in WSLg nesting)
   - No CFFI string decoding errors from nested compositor quirks
   - GPU acceleration works properly for shm buffer rendering
   - =river_layer_shell_v1= is already bound — the native launcher works out of the box

* Design vision

The long-term goal is a Wayland window manager that captures the spirit of the Lisp Machines:

- *Live programmability*: eval expressions from keybindings, redefine layouts at runtime, inspect and manipulate live window objects from the REPL
- *Native CL app launcher*: a fuzzel-like overlay rendered in CL, with fuzzy search, keyboard navigation, and programmable app list — no external process needed
- *Programmatic window placement*: window rules to place specific apps on specific outputs with specific sizes, like StumpWM's =define-window-preference=
- *Hooks*: user-defined functions triggered on window creation, focus change, layout switch, output hotplug
- *Inspectable everything*: =(describe some-window)=, =(inspect some-output)=, eval expressions that manipulate live state
- *Mode line*: a status bar showing window state, layout, clock — rendered in CL via layer-shell
